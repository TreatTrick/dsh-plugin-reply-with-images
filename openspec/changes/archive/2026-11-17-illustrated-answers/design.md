## Context

插件目前由 Host 端搜索、保存并返回 Markdown。自动图片建议作为系统提示的一段文字，只列出外观、地点、物体、自然和比较；本机对应的长篇人物新闻回答确认过已提供图片工具，但模型最终没有调用它们。Host 包也尚无 `dsh.client` 浏览器入口。

DSH 现有聊天客户端会渲染 Markdown 图片，并支持含图消息表格；图像下载错误时会退回可读替代文字。浏览器扩展可以随插件包作为独立 `dsh.client` 入口加载。因此不需要改 Harness 主仓库，也不需要创建一套新的 Host 和 Web 图片存储。

## Goals / Non-Goals

**Goals:**

- 明确覆盖长篇人物、组织、新闻事件、商品、地点和对比回答的自动配图指导。
- 将“按模型选定主题搜索、选择首个可用结果、下载保存并返回可插入的来源标注 Markdown”收敛到一次 Host 工具调用，同时保留原分步搜索和选图工具。
- 用可选客户端扩展让含图 Markdown 表格在窄屏和宽屏上均易读，并为普通 Markdown 图片提供键盘可访问的放大查看。
- 继续使用附件持久化、现有官方 Connection 媒体路由和既有 URL/DNS/字节限制。

**Non-Goals:**

- 保证模型在任何回答中一定会调用图片工具；调用策略仍由当前模型依据明确系统提示自主执行。
- 改写 DSH 的 Markdown 解析器或聊天主仓库，生成图片、识别图片内容、断言搜索结果中人物的身份，或保证未知许可图片可再发布。
- 更换搜索提供方或依赖会话后的人工修补来添加图片。

## Decisions

### 一次调用完成取图

添加 `reply_images_prepare`，接受有序的主题、搜索词和可访问替代文字。每项通过现有受限 Provider 搜索，选用该搜索返回的首个候选并沿用 `embed` 持久化，汇总为对应 Markdown、来源和许可及逐项警告。该调用逐项顺序执行，既受每轮搜索/图片预算、取消信号和插件卸载生命周期约束，也让单项失败不丢弃已成功的图。

保留 `reply_image_search` 和 `reply_images_embed` 供模型在需要比较候选标题、精确挑选图源时使用。高级路径与简化路径共享相同候选与附件能力，避免重复的安全实现。

**替代方案：**仅强化原提示词并保留两个工具不变，工作量较小，但这两个工具在参考会话中已经可用仍被完全跳过，步骤数也没有降低。提前无条件搜索会查询主题不相关的图并消耗网络及隐私预算，所以不采用。

### 明确的触发与克制

当 `automatic` 开启时，Host 系统提示直接要求较长的人物介绍、新闻或事件综述、商品和地点回答评估 1–3 个主题并调用简化工具，同时建议来源明确的公开人物图片，禁止将未核实的个人图片表述成对指控的证据。短答、抽象主题、代码和纯文字要求仍跳过。是否调用由模型执行，没有在 Agent 请求前自动预搜。

默认将每轮搜索和展示预算都调整为 3 张。简化工具的主题数量不能超过单轮剩余搜索预算或图片预算；各项顺序尝试，并保留可用图及失败诊断。现有用户自定义预算仍生效。

### Markdown 承载位置与外观

Host 返回已有的持久 Markdown 图片和溯源说明；模型根据内容把它放在相关段落旁。可使用两列含图表格表达关键人物或实体索引，也可用多列含图表格表达场景比较；单张图片不强制进入表格。客户端从 DSH `dsh.client` 入口注册本地表格样式与图片交互，不读取图片目的地、不改写正文、不自行下载或保存图像。

样式只针对包含图片的 Markdown 表格：第一列包含单张图片时作为紧凑图像栏；多列图像对比平分空间；加载图沿用 DSH Markdown 图片处理和 alt 回退。客户端不安装时，表格和图片仍为有效 Markdown。

普通 Markdown 图片由扩展的委托点击和键盘事件打开原生 `<dialog>` 查看器，按需加载大图、保留图片 alt、支持 Escape 和关闭按钮；不截取链接中的图片以免改变原本的导航语义。对于 DSH 已包在原生按钮中的图片，保留宿主原有的放大交互。视口缩放使用 `max-width`/`max-height` 约束，图片加载失败继续由原 Markdown 渲染器回退。增强仅作用于宿主 `data-chat-group-part="response"` 区域，避免影响输入框、头像及工具卡。

**替代方案：**改成 DSH Assistant 原生图片内容块可以使用内置图片画廊，但当前 Host 工具不能重写最终 Assistant 消息块；需要改 Harness 主仓库或创建不与当前工具输出衔接的客户端注册，因此不采用。直接建立 CSS 来改变所有表格会影响与图片无关的内容，故按图片内容选择。

## Risks / Trade-offs

- [工具指导仍由模型决定是否遵从] → 使用覆盖真实失败类别的直接要求、降低为一次工具调用，并通过提示集成测试锁定模型可见工具描述；真实 Provider 的行为仍需要发布后手动验证。
- [搜索提供方的首位候选可能不相关] → 查询提示保持简洁且针对单一实体；失败逐项显示并保留高级精确选图接口；客户端与 alt 文本不宣称已检查照片内容。
- [新增浏览器捆绑清单不匹配某些已安装版本] → 限制为没有额外运行时依赖的 Web 客户端入口，并继续由 Markdown 原文提供回退；在记录过的 Harness SDK 基线编译客户端产物。
- [长答增加请求和下载] → 每轮搜索数及图片数默认各为 3、顺序执行、受图片大小和请求超时约束，并允许用户关闭 automatic 或覆盖预算。
- [表格布局与图片桌面增强在某客户端配置下不可用] → 分别测试响应式 CSS 和无增强的原始 Markdown；核心内容不依赖样式类或查看器。

## Migration Plan

保持 Host 图像工具的既有名称、输出字段、附件引用和 Web 路由不变；新增工具并发出匹配客户端入口。现有会话中的 Markdown 图片和媒体 URL无需迁移。升级后新会话即可使用更明确的自动配图提示与一次调用流程；卸载可选客户端时新旧图片仍显示为普通 Markdown。
