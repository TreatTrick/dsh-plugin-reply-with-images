# Illustrated Answers

## Purpose

Define how DSH prepares, attributes, and presents relevant images in answers.

## Requirements

### Requirement: 自动识别适合插图的回答

当 automatic 配置开启时，系统提示 MUST 明确要求模型先判断图片是否能对回答产生正面理解价值：在较长的人物、组织、新闻或事件、商品、地点、自然主题和视觉比较回答中主动调用图片准备工具，并根据章节语义选择合适的图片布局（人物或实体目录与属性对比使用 `table`，单一复杂事件或专题的多维度补充使用 `collage` 一大两小拼贴，同一主题的多瞬间或多角度展示使用 `strip` 横向排列，独立段落配图使用 `single`），将每组成功结果插入对应章节之后，不得只使用开头的聚合 Markdown。对于包含多个可视章节的长篇人物、新闻或事件综述，模型 MUST 规划多个互不重复的图片区块并按语义组合不同版式，不得为凑齐张数插入不相关图片；仅当相关视觉主体不足或剩余预算不足时降级。短答、代码、抽象主题和纯文字请求 MUST 被指导为不搜索图片。配置关闭时 MUST 继续只在用户明确要求图片时使用图片工具。

#### Scenario: 长篇多章节综述组合多种版式

- **WHEN** 用户要求详细介绍一位公众人物及相关复杂事件，且 automatic 已开启并存在人物介绍、核心事件与系列现场等多个可视章节
- **THEN** 模型收到先判断视觉价值再按语义选择 `table`、`collage`、`strip` 等版式的明确指引，调用单次图片准备工具，并将每组成功图片插入各自对应章节之后

#### Scenario: 只有一个相关视觉主体时降级

- **WHEN** 用户要求的长答只有一个适合展示的视觉主体，或剩余预算不足以支持多组图片
- **THEN** 模型可以准备单个主题或单张图片，并继续完成文字回答

#### Scenario: 纯文字、短答或抽象主题

- **WHEN** 用户要求短答、纯文字回答，或咨询代码、数学推理及抽象概念
- **THEN** 模型收到跳过装饰性配图的指导

#### Scenario: 用户关闭自动配图

- **WHEN** automatic 已关闭且用户没有要求图片
- **THEN** 系统提示禁止主动调用自动和分步图片工具

### Requirement: 单次调用准备主题配图

系统 MUST 提供 `reply_images_prepare`，支持模型在一次调用中提交 1–5 个有序图片区块（`topics[]`），每个区块可声明布局类型 `layout`（`single`、`table`、`collage`、`strip`，默认为 `single`），并支持向后兼容的单查询模式（`query`、`alt` 及可选多图张数 `count`）以及多子查询模式（`items[]`）。工具 MUST 按单轮剩余搜索预算与剩余图片预算分别原子预留整批需求（单查询取多图仅消耗一次搜索预算及对应张数图片预算），在单次搜索内支持候选下载失败顺延尝试下一可用候选并按 `attachmentId` 去重，沿用现有安全 Provider、附件持久化能力及取消/卸载排空契约。每个区块 MUST 独立返回布局类型、对应章节 `placement` 插入提示、可直接插入正文的 `markdown`、供表格单元格使用的 `tableMarkdown`、图片元数据数组及独立警告，不得因单个区块或单张候选失败丢失其余已成功图片。原有 `reply_image_search` 和 `reply_images_embed` MUST 继续可用。

#### Scenario: 一次调用准备多种布局区块

- **WHEN** 模型提交包含 `table`（多人物 `items`）、`collage`（1 主图 + 2 辅图）和 `strip`（单查询 `count: 4`）的合法请求且未超剩余搜索与图片预算
- **THEN** 工具在网络请求前分别预留搜索预算与图片预算，按序完成搜索、候选容错下载与去重持久化，并为每个区块返回可直接插入正文的布局 Markdown、统一来源说明及对应 `placement`

#### Scenario: 向后兼容旧版单图主题入参

- **WHEN** 模型仅提交旧版 `{ topic, query, alt }` 而不提供 `layout`、`count` 或 `items`
- **THEN** 工具按 `layout: "single"` 且目标 1 张图执行，并保持原有输出字段完整可用

#### Scenario: 单查询多图时遇到坏图或重复图顺延回退

- **WHEN** 某次 `collage` 或 `strip` 请求需要从单次搜索结果中保存 3 张图，且首个候选下载失败或与已保存图片内容哈希重复
- **THEN** 工具自动跳过失败或重复候选并顺延尝试后续候选，尽量满足目标张数，同时在警告中记录失败项而不丢弃已成功图片

#### Scenario: 区块数或搜索/图片需求超过剩余预算

- **WHEN** 提交的区块总搜索数超过剩余搜索预算，或总目标图片数超过剩余图片预算
- **THEN** 工具拒绝超额输入且不得在网络或附件服务上执行超额工作

#### Scenario: 拼贴或横向图集部分失败自动降级

- **WHEN** 一个 `collage` 区块仅成功保存 2 张或 1 张图片，或一个 `strip` 区块仅成功保存 1 张图片
- **THEN** 工具分别将其输出平滑降级为 2 图横向排布或普通单图 Markdown，避免生成残缺的三格拼贴标记，并保留失败原因警告

#### Scenario: 插件卸载或请求取消

- **WHEN** 图片准备期间当前轮取消或插件开始卸载
- **THEN** 网络工作停止并按现有附件写入排空契约结束

#### Scenario: 部分图源失败

- **WHEN** 一项搜索无结果或一张图片下载保存失败而其他主题成功
- **THEN** 工具保留成功图片并对失败主题返回可读警告，模型仍可插入其他主题图片

### Requirement: 图片分组可读且有来源说明

当回答包含人物/实体目录、视觉对比、一大两小拼贴或横向多图条时，工具输出的 Markdown MUST 保持标准 Markdown 可读性：表格布局继续使用标准 Markdown 含图表格；`collage` 与 `strip` 布局 MUST 将同组图片排布在同一标准 Markdown 段落内，并在紧随其后的脚注行汇总列出所有图片的来源、作者与许可说明；当且仅当图片目标为 HTTP(S) URL 时附加无害的布局片段标识（`#dsh-layout=collage&group=...` 或 `#dsh-layout=strip&group=...`），Desktop 端本地文件图片通道 MUST 不附加 URL 片段以防破坏原生路径读取。每张图片 MUST 保留准确 alt 文本及工具返回的来源与许可信息，不得将未知许可描述为可再发布许可，也不得将未经核实的图片描述为所涉人物或不当行为的证据。

#### Scenario: 拼贴与横向图集保持标准 Markdown 降级可读

- **WHEN** 工具生成 `collage` 或 `strip` 区块的 Markdown 且目标地址为 Web 端 HTTP(S) 媒体 URL
- **THEN** 同组图片位于同一段落并携带 `#dsh-layout=` 与 `group` 片段标识，紧随其后提供汇总来源与许可脚注；未加载客户端增强时仍可直接渲染全部图片与出处

#### Scenario: Desktop 本地图片路径保持纯净

- **WHEN** 插件运行在 Desktop profile 并通过 `imageDestination` 生成本地图片路径
- **THEN** 生成的 Markdown 图片地址不附加 `#dsh-layout=` 片段，确保桌面端原生文件通道正常加载图片

#### Scenario: 人物目录与并列图片组

- **WHEN** 模型创建人物目录或视觉对比并将图片放入标准 Markdown 表格
- **THEN** 每个图片组在原 Markdown 中仍与相邻的名称、说明和来源对应

#### Scenario: 结果未能验证图片身份或许可证

- **WHEN** Provider 仅返回标题和来源，或许可状态未知
- **THEN** 输出不得声称已检查图片内容或存在再发布许可，并继续显示现有的许可证状态文字

#### Scenario: 普通单图插入回答

- **WHEN** 一个主题的图片适合配合独立段落
- **THEN** 模型可以直接插入该图的 Markdown 及其来源和许可说明，无须创建表格

### Requirement: 客户端图片表格与查看器增强

启用插件 Web 客户端入口时，DSH MUST 在 `[data-chat-group-part="response"]` 范围内以零外部依赖、可逆 `ctx.effect()` 方式增强三种图片布局与查看器：

1. **表格样式**：将含图 Markdown 表格呈现为响应式人物目录行（首列紧凑 3:4 肖像裁切并优先保留上部人物构图）或等宽多列比较组；
2. **一大两小拼贴**：识别带有 `#dsh-layout=collage` 的 3 图段落并呈现为左大图跨两行、右两小图上下堆叠的圆角网格拼贴（窄屏自适应为上大图下两小图），2 图时呈现为等宽双栏；
3. **横向多图条**：识别带有 `#dsh-layout=strip` 的多图段落并呈现为等高圆角横向缩略图条，超过 3 张时隐藏溢出缩略图并在行内提供可点击的计数角标；
4. **组内多图查看器**：允许通过鼠标和键盘放大任意普通 Markdown 图片；当图片属于多图组（拼贴、横向条或含图表格）时，查看器 MUST 支持上一张/下一张按钮、`ArrowLeft`/`ArrowRight` 键盘切换、底部分页圆点及当前图片 alt 展示；仍 MUST 限制图片在可视视口内、支持 `Escape` 和明确关闭按钮并在关闭后恢复焦点。
   图片加载失败 MUST 保留 Markdown renderer 的可读错误/alt 回退。插件卸载时 MUST 彻底清理样式、监听、角标、打开的弹窗及临时属性。未加载客户端入口时，原回答 MUST 仍以普通 Markdown 图片和表格展示。

#### Scenario: 桌面与窄屏展示人物目录与对比表格

- **WHEN** Web 客户端已加载且回答包含首列带图的人物目录表格或多列对比表格
- **THEN** 首列人物图以紧凑 3:4 肖像栏呈现且保留上部人物构图，多列对比表在桌面和窄屏下均保持图片受限于列内不重叠

#### Scenario: 桌面与窄屏展示一大两小拼贴

- **WHEN** Web 客户端已加载且回答包含带有 `#dsh-layout=collage` 的 3 张有效图片段落
- **THEN** 桌面端呈现左 1 大图跨两行 + 右 2 小图上下堆叠的圆角拼贴网格，窄屏下切换为首图在上跨两列 + 两小图并排在下

#### Scenario: 横向多图条与超量计数角标

- **WHEN** Web 客户端已加载且回答包含带有 `#dsh-layout=strip` 的 4 张有效图片段落
- **THEN** 行内横向显示前 3 张等高圆角缩略图、隐藏第 4 张并在行内展示标明总数 `4` 的可点击角标；点击角标或任意缩略图可在查看器中浏览全部 4 张图片

#### Scenario: 组内多图灯箱键盘与鼠标切换

- **WHEN** 用户通过点击或键盘激活拼贴、横向多图条或含图表格中的一张图片
- **THEN** 查看器打开并显示当前图片、alt 文本、上一张/下一张按钮与分页圆点；按 `ArrowRight`/`ArrowLeft` 或点击按钮与圆点可切换同组图片，按 `Escape` 或点击关闭后返回原触发图片焦点

#### Scenario: 插件卸载或客户端未启用

- **WHEN** 插件客户端卸载、图片 URL 不可用或 DSH 客户端增强未加载
- **THEN** 卸载后不残留临时属性、角标、样式或弹窗；图片错误仍由 Markdown 回退处理，正文、表格与来源不会因增强缺失而丢失

#### Scenario: 鼠标或键盘放大查看

- **WHEN** 用户激活一张普通 Markdown 图片
- **THEN** 图片在键盘可关闭、含替代文字的视口查看器中放大，Escape 或关闭操作返回回答

### Requirement: 默认预算与逐图回退

系统 MUST 将默认每轮图片搜索预算设为 `6`（可配置上限 `12`）、默认每轮图片展示预算设为 `8`（可配置上限 `16`）、默认每次搜索候选数设为 `10`（可配置上限 `20`），并继续接受用户有效的配置覆写。无结果、预算不足和逐图存储错误 MUST 允许模型完成有用的文字回答，并提供说明失败原因的工具结果。

#### Scenario: 默认多布局配图预算

- **WHEN** 插件以默认配置加载
- **THEN** 单轮默认允许最多 6 次图片搜索、最多 8 张展示图片，每次搜索默认保留最多 10 个候选

#### Scenario: 用户自定义较小或较大有效预算

- **WHEN** 配置将 `maxImagesPerTurn` 或 `maxSearchesPerTurn` 覆写为合法范围内的自定义值
- **THEN** 工具预算校验和系统提示均遵从配置值

#### Scenario: 全部图源不可用

- **WHEN** 所有当前 Provider 均失败或找不到可用候选
- **THEN** 工具返回有界警告，模型能够继续提交无图文本回答
